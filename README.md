# ltv-prediction

Прогноз пожизненной ценности пользователя (LTV): суммарный GMV в Поиске и Каталоге
за следующие 30 дней по истории ежедневной активности. Данные — E-CUP 2026 (Ozon Tech),
трек 3; соревнование завершено, использовано как проект. Метрика — RMSLE.

## Данные

30.6 млн обезличенных записей об активности 250 000 пользователей за 2025-01-01 … 2026-02-13.
Каждая строка — сводка за один активный день: поиск, каталог, добавления в корзину, заказы,
стоимость заказов (`gmv`). Ряды разреженные — строки есть только за дни с активностью
(медиана 102 активных дня на пользователя).

Цель — предсказать сумму `gmv` каждого пользователя за 2026-02-14 … 2026-03-15.

## Подход

Задача сводится к регрессии на пользователя. Для каждого пользователя признаки считаются
по истории до даты среза, целевая переменная — сумма `gmv` за 30 дней после среза.

- **Признаки (по окну до среза):** активность и стаж (число активных дней, tenure, recency),
  RFM (суммарный и средний `gmv`, доля дней с покупкой), воронка (searches → cart → order,
  конверсии), свежесть — суммы `gmv`/заказов/поисков за последние 7/14/30/60/90 дней и тренд
  «свежие 30 дней против предыдущих 30».
- **Обучение на нескольких срезах:** выборка собирается по четырём сдвинутым на месяц срезам,
  чтобы модель училась отображению «история → будущие 30 дней» на разных точках календаря.
- **Модель:** LightGBM в пространстве `log1p(target)` с MSE — RMSE в логарифме и есть RMSLE.
  Прогноз возвращается через `expm1`, отрицательные значения зануляются.
- **Разреженность:** пользователи без активности в окне получают нулевые счётчики и большой
  `recency`, без дозаполнения рядов нулевыми днями (иначе данные раздуваются до ~100 млн строк).

## Результаты

Валидация на последнем полностью размеченном окне (признаки до 2026-01-15, цель — следующие
30 дней), 250 000 пользователей:

| прогноз | RMSLE |
|---|---|
| **LightGBM** | **1.693** |
| константа — среднее | 3.175 |
| все нули | 3.204 |

Модель почти вдвое лучше тривиальных базлайнов. Наиболее весомые признаки — `tenure_days`,
суммарный `gmv`, `searches_sum`, `recency_days` и свежие окна поиска: ценность пользователя
определяется давностью, частотой и объёмом активности.

Возможные расширения: двухэтапная модель для нулевой активности (классификатор «купит ли» +
регрессор «на сколько»), BTYD-модели, признаки сезонности.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

python src/train.py               # обучение + валидация RMSLE, сохраняет model.txt
python src/predict.py             # submission.csv на всех 250k пользователей
```

Путь к данным задаётся флагом `--data` (по умолчанию `train.parquet` из загрузок).

## Структура

```
src/
  data.py      признаки по окну истории, целевая переменная, сборка выборки (polars)
  train.py     обучение LightGBM на log1p, валидация RMSLE, важность признаков
  predict.py   прогноз на 30 дней вперёд, формирование submission.csv
```

Обработка 30 млн строк — на polars; модель — LightGBM на CPU.
